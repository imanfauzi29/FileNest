\# Feature 07 — Monitoring



\## 1. Overview



Monitoring allows users to monitor file and folder changes within registered Managed Folders in real time or in the background.



The application detects filesystem events and records them as monitoring activities.



Users can view recent changes, manage folder watchers, configure monitoring rules, and receive alerts for relevant events.



\### Goals



\- Monitor file and folder changes.

\- Detect file creation, modification, deletion, and movement where supported.

\- Display filesystem activity in real time.

\- Manage monitored folders.

\- Configure monitoring rules.

\- Provide alerts for selected events.

\- Maintain monitoring history.

\- Integrate monitoring events with the application's History system.



Monitoring must only operate within registered Managed Folders.

\## 15. Monitoring Workflow



\### Starting Monitoring



1\. User registers a Managed Folder.

2\. User enables monitoring for that folder.

3\. Backend validates the folder scope.

4\. Watchdog creates the watcher.

5\. Watcher begins collecting filesystem events.

6\. Events are placed in the event processing queue.

7\. Backend normalizes and deduplicates events.

8\. Events are persisted to SQLite.

9\. UI receives updated monitoring data.



\### Processing Events



1\. Receive filesystem event.

2\. Validate event path against Managed Folder scope.

3\. Apply debounce and deduplication.

4\. Resolve event type where possible.

5\. Collect relevant file metadata.

6\. Persist event.

7\. Evaluate matching monitoring rules.

8\. Create alerts or analysis requests when applicable.



Do not send every raw filesystem event directly to AI.



\### Application Restart



\- Restore eligible watcher configurations.

\- Revalidate Managed Folder availability.

\- Start valid watchers.

\- Report folders that cannot be monitored.

\- Avoid creating duplicate watchers.



\## 16. API Requirements



The API must support at least the following operations.



\### Get Monitoring Status



`GET /api/monitoring/status`



Returns the global monitoring service status.



\### Get Monitoring Summary



`GET /api/monitoring/summary`



Returns monitoring statistics for the selected time range.



\### Get Activities



`GET /api/monitoring/activities`



Query parameters:

\- event\_type

\- managed\_folder\_id

\- source

\- start\_date

\- end\_date

\- search

\- page

\- page\_size



Returns paginated monitoring events.



\### Get Event Details



`GET /api/monitoring/activities/{event\_id}`



Returns complete event details.



\### Get Watchers



`GET /api/monitoring/watchers`



Returns all registered watchers.



\### Create Watcher



`POST /api/monitoring/watchers`



Creates a watcher for a registered Managed Folder.



\### Update Watcher



`PATCH /api/monitoring/watchers/{watcher\_id}`



Updates watcher configuration or state.



\### Remove Watcher



`DELETE /api/monitoring/watchers/{watcher\_id}`



Removes the watcher without deleting the Managed Folder.



\### Get Rules



`GET /api/monitoring/rules`



Returns monitoring rules.



\### Create Rule



`POST /api/monitoring/rules`



Creates a monitoring rule.



\### Update Rule



`PATCH /api/monitoring/rules/{rule\_id}`



Updates a monitoring rule.



\### Get Alerts



`GET /api/monitoring/alerts`



Returns paginated alerts.



\### Update Alert



`PATCH /api/monitoring/alerts/{alert\_id}`



Updates alert read or dismissal status.



These endpoints are proposed API contracts. Adapt them to the existing backend conventions.

\## 18. Technical Requirements



\- Use Watchdog for filesystem event monitoring.

\- Run watchers in the Python backend.

\- Persist watcher configurations in SQLite.

\- Persist monitoring events in SQLite.

\- Use a background event processing queue.

\- Implement debounce and deduplication.

\- Validate every event path against registered Managed Folders.

\- Avoid following symbolic links, junctions, and reparse points by default.

\- Handle inaccessible directories and permission errors.

\- Prevent duplicate watchers.

\- Support background monitoring while the desktop application is minimized.

\- Use Tauri notifications where appropriate.

\- Keep monitoring resource usage controlled.

\- Avoid unnecessary AI calls for routine filesystem events.



\## 19. Safety Constraints



\- Only registered Managed Folders may be monitored.

\- Do not scan or monitor the entire disk automatically.

\- Never trust raw filesystem event paths without validation.

\- Do not follow symbolic links, junctions, or reparse points by default.

\- Monitoring must not modify filesystem contents.

\- Monitoring rules must not perform unrestricted mutations.

\- All proposed mutations must go through Review Changes.

\- Watcher removal must not remove physical folders.

\- Alert dismissal must not delete monitoring events.

\- Record monitoring configuration changes in History.

\- Handle event bursts without unbounded memory growth.
